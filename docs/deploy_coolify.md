# Production Backend: Oracle Cloud and Coolify

This runbook deploys PostgreSQL and n8n on an Oracle Cloud VM managed by
Coolify. The Astro frontend is deployed separately on Vercel.

## Target

```text
Oracle Cloud VM
└── Coolify self-hosted
    └── Docker Compose service
        ├── n8n
        └── PostgreSQL (not publicly exposed)
```

The first deployment may use the HTTPS hostname generated by Coolify. A custom
domain is optional for this demo.

## 1. Create the Oracle VM

In Oracle Cloud Console:

1. Open **Compute → Instances → Create instance**.
2. Name it `dental-automation-prod`.
3. Select Ubuntu 24.04 LTS.
4. Select an Always Free eligible shape available in the tenancy.
5. Allocate only Always Free eligible CPU and memory.
6. Assign a public IPv4 address.
7. Upload or generate an SSH public key.
8. Download and protect the private key if Oracle generated it.

Confirm the summary still displays an Always Free eligible configuration before
creating the instance. Availability and eligible shapes depend on the region.

## 2. Configure network access

Allow inbound TCP traffic in the VM's Network Security Group or subnet security
list:

| Port | Source | Purpose |
|---:|---|---|
| 22 | Your current public IP | SSH administration |
| 80 | `0.0.0.0/0` | HTTP and certificate challenges |
| 443 | `0.0.0.0/0` | HTTPS applications and webhooks |
| 8000 | Your current public IP | Initial Coolify dashboard |

Do not expose PostgreSQL port 5432 publicly. Do not flush the VM firewall.

Apply equivalent rules in Ubuntu using `ufw` if it is enabled:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow from YOUR_PUBLIC_IP to any port 8000 proto tcp
sudo ufw enable
sudo ufw status
```

## 3. Install Coolify

Connect using the SSH command shown by Oracle:

```bash
ssh -i /path/to/private-key ubuntu@ORACLE_PUBLIC_IP
```

Follow Coolify's current installation instructions. At the time this runbook was
written, the official installer is:

```bash
curl -fsSL https://cdn.coollabs.io/coolify/install.sh | sudo bash
```

Open `http://ORACLE_PUBLIC_IP:8000` immediately and create the administrator
account. After configuring an HTTPS dashboard hostname, remove public access to
port 8000 or keep it restricted to your IP.

## 4. Connect the GitHub repository

In Coolify:

1. Create project `Dental Clinic Automation`.
2. Create environment `production`.
3. Connect the GitHub repository.
4. Select branch `main`.
5. Select Docker Compose as the build/deployment type.
6. Set the base directory to `/`.
7. Set the Compose file to `/infrastructure/docker-compose.yml`.
8. Enable automatic deployment when `main` changes.

Do not deploy until every required environment variable has been configured.

Coolify must load only `docker-compose.yml`. Local `docker compose` commands
automatically load `docker-compose.override.yml`, which preserves the existing
bind-mounted development data and local config paths without changing the
production volumes or the repository-root config paths used by Coolify.

## 5. Configure production secrets

Use `infrastructure/.env.production.example` as the key inventory. Enter values
in Coolify's environment-variable interface, not in Git.

Generate independent secrets:

```bash
openssl rand -base64 48
```

At minimum, generate separate values for:

- `POSTGRES_PASSWORD`
- `N8N_ENCRYPTION_KEY`
- `WHATSAPP_VERIFY_TOKEN`

Never rotate `N8N_ENCRYPTION_KEY` after credentials have been stored in n8n
unless a documented credential migration is performed.

## 6. Assign the n8n HTTPS hostname

Assign an HTTPS FQDN to the n8n service using the hostname offered by Coolify.
Copy the exact hostname and update:

```text
N8N_HOST
N8N_EDITOR_BASE_URL
WEBHOOK_URL
```

Expected forms:

```text
N8N_HOST=<host-without-scheme>
N8N_EDITOR_BASE_URL=https://<host>/
WEBHOOK_URL=https://<host>/
```

Keep:

```text
N8N_PROTOCOL=https
N8N_PROXY_HOPS=1
N8N_SECURE_COOKIE=true
```

## 7. Deploy and initialize

Reload the Compose file and confirm that Coolify detects two named volumes
(`postgres_data` and `n8n_data`) plus the versioned SQL and knowledge files as
Compose configs, not persistent directories.

Deploy from Coolify and wait until both containers are healthy. On a new empty
PostgreSQL volume, the initialization and migration configs run automatically.

For an existing database, apply pending migrations explicitly after taking a
backup:

```bash
docker exec -i dental_postgres psql \
  -U "$POSTGRES_USER" \
  -d "$POSTGRES_DB" \
  < infrastructure/migrations/001_extend_appointments.sql
```

Do not assume initialization scripts rerun on a non-empty PostgreSQL volume.

## 8. Configure n8n

1. Open the HTTPS n8n URL and create the owner account.
2. Import the workflows from `infrastructure/n8n_workflows`.
3. Create or reassign PostgreSQL, Telegram and SMTP credentials.
4. Confirm every environment-backed integration resolves.
5. Activate only the workflows being tested.

Credential IDs stored in exported JSON may not match a fresh n8n instance.

## 9. Backups

Before enabling public traffic:

1. Configure a daily PostgreSQL backup in Coolify.
2. Send backups to storage outside the VM.
3. Define retention.
4. Perform at least one restore test.

A configured backup without a restore test is not considered verified.

## 10. Smoke tests

Verify:

- n8n and PostgreSQL report healthy.
- PostgreSQL is not reachable publicly on port 5432.
- n8n loads exclusively over HTTPS.
- `/healthz` returns success.
- The WebChat workflow responds with test data.
- A test conversation is persisted.
- A Cal.com test booking is recorded.
- Failed workflow execution logs are visible.

Only after these checks should the n8n URL be configured in Vercel.
